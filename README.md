# CYBERWALL — смена ID игроком

`change_id.py` — самостоятельный консольный сценарий для гейта, Python 3.11+.
Положи этот репозиторий рядом с репозиториями
`CyberpunkPcRfidReader`, `CyberpunkIdPrinter`, `TiMini-Print` в общей родительской папке.
Код библиотек в этот репозиторий не копируется.
## Установка и запуск на Windows

В терминале из корня нового репозитория:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\change_id.py
```

Нужны актуальные версии соседних библиотек. TiMini — чистый checkout ревизии
`679fc0650e61c7ab28b44542b9b9ba000e45aa78`, которую требует текущая библиотека
CyberpunkIdPrinter; Git должен быть доступен в PATH. Существующий рабочий TiMini
из тестов принтера можно использовать без повторной установки проекта.

В `change_id.toml` задай адрес сервера и принтера. Пользователь БД — `gate`.
Он должен иметь SELECT на `main` (используются `card_id`, `id`, `name`) и EXECUTE
на `changeId`. Процедура сама управляет своей транзакцией; скрипт не делает UPDATE.
Сигнатура: `changeId(IN cardId, OUT newId, OUT errCode)`, коды 0 — успех, 1 — аккаунт отсутствует.

Пароль можно ввести при первом обращении к БД: он остаётся только в памяти процесса.
Либо укажи `password` в отдельном `change_id.local.toml` и запускай:

```powershell
.\.venv\Scripts\python.exe .\change_id.py --config .\change_id.local.toml
```

Отдельный файл может содержать только переопределяемые разделы/поля: остальные
значения берутся из встроенных значений по умолчанию. Переменная окружения
`CYBERWALL_DB_PASSWORD` имеет приоритет. Сам скрипт не сохраняет пароль.

Без `change_id.toml` скрипт также запускается со встроенными настройками.
Пути к библиотекам всегда считаются от файла скрипта, а не рабочей папки терминала.
Для печати используется текущий `LabelPrinter`, режим этикеток 40×30 мм,
центрирование (`offset_x_mm=0`). Смещение и движение бумаги настраиваются.
Параметры feed=15 / retract=25 мм взяты из текущего `labels_v2.py`.

## Сценарий

1. Выбрать «Сменить ID», приложить карту. До начала смены можно отменить.
2. Проверить имя и подтвердить начало. Пустой Enter ничего не подтверждает.
3. Получить новый ID; первая печать начинается автоматически.
4. Подтвердить, что наклейка напечаталась и наклеена **ВЗАМЕН** старой, повторить
   печать того же номера либо перейти к заполнению готового пустого шаблона.
5. В ручном режиме написать ID, затем ввести его с наклейки. Пробельные символы
   допускаются, требуются девять цифр 0–9. После пяти ошибок — направление на мастерку.

Ожидание карты не ограничено. Esc / Ctrl+C отменяет ожидание на Windows;
на Linux можно ввести `:b` и Enter. На экранах до вызова процедуры доступно `:b`.
После принятия подтверждения и сохранения намерения вызвать `changeId` отмена,
`:q`, Esc и Ctrl+C не завершают операцию. Закрыть окно средствами ОС возможно,
но повторный запуск автоматически возвращает сохранённый этап.

При отсутствии бумаги / открытой крышке, перегреве или низком напряжении
скрипт переходит к ручному заполнению и просит затем сообщить мастерам.
При обрыве Bluetooth пробует подключиться заново. Если связь восстановлена,
проверяет у пользователя результат прерванной печати, не дублирует её автоматически.
Если подключиться не удалось — ручной режим. Неизвестная ошибка позволяет повторить
печать или перейти к ручному режиму; число добровольных повторов не ограничено.

Принтер сохраняет подключение между операциями. Подтверждение замены наклейки
считается также подтверждением её снятия с ленты. Перед повторной печатью
скрипт отдельно просит убрать доступные наклейки. Из UNKNOWN библиотека выполняет
штатную калибровку вперёд и печать, без отдельной проверки первого отпечатка.

## Восстановление и журнал

`change_id_state.sqlite3` рядом со скриптом содержит **только текущий снимок операции**.
Это служебное сохранение, не технический журнал и не история действий. Оно обязательно
работает даже при выключенном логировании. Снимок записывается транзакционно через
SQLite с `synchronous=FULL` до внешнего действия. Файл не удаляется при успешном
завершении: внутри атомарно сохраняется пустое состояние `idle`.
Не удаляй и не переноси его во время незавершённой смены. Рабочая папка должна быть
доступна для записи и находиться на локальном диске. Не запускай одну копию сценария
из нескольких разных папок на одном гейте: блокировка действует на папку установки.

| Сохранённый этап | После перезапуска |
|---|---|
| Ожидание карты / поиск / подтверждение | Продолжить соответствующий этап, отмена разрешена |
| `change` | Повторить неподтверждённую смену для того же card_id в пределах оставшихся попыток |
| `print` | Автоматически напечатать уже сохранённый новый ID |
| `printing` | Спросить о результате: задание могло успеть напечататься |
| Подтверждение результата | Снова показать вопрос о наклейке |
| Подготовка повтора / ручное заполнение / проверка | Вернуться на тот же экран с тем же ID |
| Финальный экран | Повторить результат или направление на мастерку; после подтверждения открыть меню |

Если БД успела изменить ID, но процесс завершился до сохранения ответа, повторная
смена допустима по игровым правилам. Только подтверждённый и сохранённый результат
используется для наклейки. Все дальнейшие повторы печати этот ID сохраняют.
Число попыток БД (по умолчанию 3) сохраняется до вызова: принудительные перезапуски
не создают бесконечный автоматический цикл. Неудача заканчивается мастеркой.
Изменение адреса/имени БД при незавершённой операции блокируется до возврата настроек.

Финальный экран не является блокировкой гейта для дальнейших игроков: после
подтверждения сообщения операция очищается. Подтверждение нужно, чтобы перезапуск
прямо перед показом сообщения не потерял указание отправить владельца на мастерку.
Повреждённый файл состояния не стирается автоматически; работу нужно проверить мастеру.
SQLite защищает от обычного аварийного завершения процесса; аппаратная неисправность
диска или удаление файла вручную не могут быть исправлены программным восстановлением.

Технический журнал по умолчанию отключён. Включение только для отладки:

```powershell
.\.venv\Scripts\python.exe .\change_id.py --debug
```

Либо `[logging] enabled = true`. Создаётся `change_id_debug.log` с ротацией:
2 МБ и две резервные копии. Traceback и сообщения библиотек не выводятся игроку.
В файле отладки могут быть технические идентификаторы карт и данные BLE.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты не подключаются к БД или устройствам. Они проверяют ход сценария, повтор
неподтверждённой смены, отсутствие повторной смены после успешной БД, обрыв печати,
ручные ошибки, отказ диска, реальное завершение отдельного процесса, блокировку
второго экземпляра и отсутствие лога при выключенной отладке.

Перед игрой проверь на настоящем оборудовании:

- Успешную смену и вторую карту без перезапуска; печать и положение на этикетке.
- Выход при ожидании карты, незаписанную карту, отключение считывателя.
- Отсутствие бумаги / открытую крышку и успешное ручное завершение.
- Отключение принтера во время печати и повтор того же ID.
- Закрытие окна после смены ID, во время печати и при ручном вводе; восстановление.
- Недоступность БД и потерю связи во время CALL; направление на мастерку.
- Повторные Enter во время ожиданий; отсутствие случайных подтверждений.

Реальное оборудование и сервер из этой среды не проверялись. Автотесты не
подтверждают механическую калибровку, качество печати или доступы пользователя gate.



## Фоновое подключение принтера

При запуске программа сразу запускает фоновое подключение. Меню остаётся доступным.
После подключения связь проверяется каждые `connection_check_interval` секунд
(по умолчанию 2). При обрыве начинаются повторные попытки с паузой
`reconnect_delay` (по умолчанию 5 секунд). Эти попытки продолжаются также в ручном
режиме, но сами не запускают печать и не меняют выбранный режим операции.

На этапе печати `connect_attempts` задаёт число ожидаемых попыток подключения.
Если фоновая попытка уже выполняется, она считается первой; завершённые ранее
неудачи не учитываются. При исчерпании лимита программа переходит к ручному
заполнению. В текущем конфиге оставлена 1 попытка. Внутри библиотеки каждая попытка
выполняется без дополнительных повторов, поэтому число попыток не перемножается.
`scan_timeout` и `timeout` по-прежнему ограничивают этапы поиска/подключения,
а не общее время всей серии. Между попытками действует `reconnect_delay`.

Проверка связи и переподключение сериализованы с печатью: фон не вмешивается
в движение бумаги. Переподключение не повторяет задание. При выходе фоновые
задачи останавливаются, соединение закрывается.
